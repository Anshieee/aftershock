- **Why:** GitHub Actions had been failing on `main` since 2026-10-19 (`Typecheck` success → `Unit tests (vitest)` **failure** → `Build` skipped: https://github.com/Anshieee/aftershock/actions/runs/39337700559), and the M9/M10 branch failed the same way (https://github.com/Anshieee/aftershock/actions/runs/39726097799). - **Reproduced matrix (clean clones, committed lockfiles, no reused worktrees):**
  - `main` `57ddfb4`, root suite: Node 20.20.2 → **7 failed** (`src/lib/api.test.ts` ×4, `src/pages/ExportPage.test.tsx` ×3, all from `Export endpoint returned a non-blob body`); Node 24.22.0 → **531 passed / 13 skipped**.

- **Two root causes (both now fixed on this branch):**
  1. `src/lib/api.ts` `parseExportBlob` used `payload instanceof Blob` — realm-bound, so under Node 20 + jsdom the runtime's own `Blob` class (returned by `Response.blob()`) was rejected. Fixed with a WebIDL brand check alongside a guarded `instanceof`; **non-Blob bodies still throw** (negative-control test added). The same fragility was real in browsers (iframe/worker Blob).
  2. With a server-only install, vite cannot resolve `pdfkit` from the out-of-root importer `netlify/functions/export-report.mjs`, hands the runner a bare id, and **inlines** pdfkit — whose package-scoped `#standard-fonts/*` `imports` map then resolves against `server/package.json` and fails → every PDF export answered **500**. Fixed by externalizing `pdfkit` in `server/vitest.unit.config.js`, with a regression guard that renders a real PDF through the production handler (asserts `%PDF-`, `/Helvetica`, `/Helvetica-Bold`, `%%EOF`) and fails loudly if the fix is reverted.
- **CI now executes what the rules require:** `.github/workflows/ci.yml` runs two jobs, each on **Node 20 and Node 24** — `frontend` (typecheck → root suite → build) and `server` (`npm ci --prefix server` → `npm --prefix server test`, installed independently so a resolution regression cannot hide behind the root `node_modules`). `engines: { node: ">=20" }` declared in both manifests.
- **Local verification (commands in the PR):** root suite **533 passed / 13 skipped / 0 failed** on Node 20 **and** Node 24; `server/` suite **298 passed / 0 failed** on Node 20 **and** Node 24; `npm run typecheck` clean; `npm run build` succeeded; negative control confirms a failing `server/` test fails the server check.

Protection is now configured and **verified by an authenticated API read-back**: required status checks = `typecheck, root tests, build (node 20)`, `typecheck, root tests, build (node 24)`, `server unit tests (node 20)`, `server unit tests (node 24)`; `allow_force_pushes=false`, `allow_deletions=false`.
