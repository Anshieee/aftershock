# UX Audit — 2026-10-19 (before screenshots)

Reference captures under `docs/design/assets/2026-10-19/before/` (production
deploy `6ad5be2ceeaad83914613fb6`). Home captured at 1440×900, 1366×768 and
390×844; secondary pages at 1440×900; graph extra at 390×844.

## Diagnosis — homepage (`/`)

The homepage already carries the right *words* ("What would you like to
investigate?") but fails the composition brief in five concrete ways.

1. **Dashboard composition, not an entry experience.** The hero sits top-left
   in a `max-w-3xl` column inside a 1152px shell, leaving a large dead band
   on the right and a content pile that starts at the very top of the
   viewport. Nothing is centered or vertically balanced (`home-desktop.png`,
   `home-laptop.png`).

2. **Two competing full-width cards with equal-weight CTAs.** "Try guided
   example" (indigo primary) is followed by "Or start from your own
   document" whose **full-width indigo "Choose a document" button** is the
   same visual weight as the primary CTA. This is exactly the
   "multiple competing CTAs" complaint: the eye has two indigo destinations
   and no focal point.

3. **Implementation detail surfaced as marketing copy in the hero zone.**
   "Seeds the live demo graph…", "Runs through the guarded, rate-limited
   API", "registered through the real import flow — the server's own
   disclosure is shown verbatim". These are integrity internals stated as
   product copy; they belong on demand, not in the first viewport's reading
   path.

4. **A wall of disclaimers in the initial viewport.** The import card is
   always expanded, so accepted-formats / 10 MB / privacy lines occupy the
   first screen alongside the CTAs. Disclosures must remain honest *and*
   progressive: visible where relevant, not carpeted across the entry.

5. **Weak rhythm below the fold.** Stacked full-width cards (guided, import,
   featured) with no typographic hierarchy between them — everything is a
   boxed section with the same border/radius treatment.

## Diagnosis — content and system

- Sidebar (`Layout.tsx`): structure is close to the brief (240px, five
  primary areas + one secondary "Knowledge Graph", diagnostics behind a
  `details`). Two nits: the entry is labeled **Overview** rather than
  **Home** (the brief's destination list), and the standalone
  "GUIDED-DEMO BUILD" line is an implementation status sitting in the nav
  column rather than inside the diagnostics area.
- Tokens (`tailwind.config.ts`): the shipped palette ≈ but ≠ the approved
  brand palette. Sage matches exactly; paper/ink/indigo/lavender/amber/red
  are approximations (e.g. ink `#2B2922` warm-brown vs approved dark-ink
  `#27283B`; brand `#52489C` vs indigo `#665C91`; lavender only exists as
  a washed `#EDEBF6`). The system needs the approved values plus derived
  muted/border tints frozen in the config so no page invents its own.
- Typography: Source Serif 4 / Inter / Bodoni Moda are already self-hosted
  (Fontsource, properly licensed) — keep them; hero needs a larger, tighter
  display scale now that it is the focal point.
- Import honesty requirements that shaped the audit: the file picker is a
  real native input (`#import-input`), selection states never claim
  analysis/registration success, and Bibliography/DOI affordances are
  truthfully disabled. None of that may regress in the redesign — the
  redesign moves *where* these appear (progressive disclosure), not
  *whether* they exist (`e2e/landing.spec.ts` pins this contract).

## Mobile notes (`home-mobile.png`)

Header stacks wordmark + the full nav list above the hero, so the primary
action requires scrolling; nav as a horizontal compact row on mobile clears
the first viewport for hero + launcher.
